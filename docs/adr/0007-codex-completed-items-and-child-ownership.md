# Codex completed items and child ownership

Codex now records visible user input and file changes as `event_msg.item_completed` items. The older `user_message` and `patch_apply_end` events are absent in current rollouts. Ignoring this transition caused valid conversations to fail the one-user/one-assistant threshold and silently disappear from indexing.

Normalize completed UserMessage, AgentMessage, FileChange, CommandExecution, and McpToolCall items into the existing parser vocabulary. Completed user messages own their turn; assistant messages and tools deduplicate by identity. Unmirrored assistant output is retained when a completed item has not yet reached the rollout. Keep older turns, preserve repeated text under distinct identities, and deduplicate mirrored/replayed items. Do not treat raw user response items as human input: they also hold injected instructions. Unsupported visible-message encodings fail diagnostically and retain refresh work. Child-only addressed agent messages preserve delegated requests with explicit attribution.

Provider metadata identifies Codex children and parent thread IDs. Child evidence is materialized under the parent; new standalone child sessions are skipped. Historical rows remain directly inspectable, marked `is_subagent=1`, and excluded from top-level consumers. Match spawn requests to child artifacts by identity, never ordering. Explicit user-thread classification preserves independent forks. Child transcript rendering excludes timestamped inherited history preceding child creation.

Keep source reading local and offline for now. The installed app-server protocol offers typed `thread/read`, `thread/turns/list`, and `thread/items/list` APIs; paginated retrieval is a promising future adapter, but the latter methods are experimental and add a runtime dependency to historical/offline indexing. Completed rollout items are still a compatibility surface, not a promised stable public API. Maintain representative behavior fixtures and surface unsupported encodings instead of silently widening raw-message ingestion.

Register Stop, Interrupt, SubagentStop, SessionEnd, and SessionStart. The first three queue ordinary refreshes, SessionEnd forces a final refresh, and SessionStart returns the shared recent-session context through `hookSpecificOutput.additionalContext` and launches detached recovery of pending jobs. Context selection remains identical to Claude/Pi and requires no model call. Short bounded retries handle transient failures; exact identity lookup handles archived sources. This preserves existing summary cadence and keeps provider hooks independent of indexing/model latency. Metadata reads are uncached and source activity timestamps are authoritative.

Normalize synchronous `request_user_input` outcomes by question ID into the shared question-selection model. Render answered prompts at the tool-result position so the user's decisions enter Clean Transcripts and summary inputs as well as queryable facts. Never infer an answer from a recommendation, question wording, or arbitrary result text. Missing/empty/cancelled/failed/malformed results remain unanswered. Asynchronous requests return only acknowledgement; their later user replies remain ordinary conversation without speculative question attribution.
